## 一、系统架构

本作品处于"云 - 边 - 端"架构中的**端 / 边**位置，与组委会提供的工业智能体对接：

```
┌─────────────────────────────────────────────┐
│  本作品：工业产线监控 APP（端 / 边）           │
│  PDA / 鸿蒙手机 · ArkUI · RelationalStore    │
│  SM2 / SM3 / SM4 加密                       │
└───────────────────┬─────────────────────────┘
                    │ MQTT over TLS 1.3 / HTTPS
                    │ JSON + 国密加密
┌───────────────────▼─────────────────────────┐
│  智能计算场景单元（云 / 后端，组委会提供）      │
│  openEuler + TDengine + openGauss + 大模型   │
└───────────────────┬─────────────────────────┘
                    │ Modbus RTU
┌───────────────────▼─────────────────────────┐
│  智能控制场景单元（现场）                     │
│  PLC / HMI / 传感器 / 丝杆滑台 / 指示灯        │
└─────────────────────────────────────────────┘
```

**关键约束：APP 严禁直连底层设备。** 所有控制指令必须经过智能计算场景单元处理与校验后转发，本作品在架构上通过 `IDataService.sendCommand()` 单点下发，天然满足该约束。

## 三、功能模块详解

### 模块一：产线运行状态监控

- 实时显示产线整体状态（运行中 / 停止 / 异常 / 复位中），状态色随值变化
- 实时显示温湿度当前值、光电传感器触发状态
- 数据刷新周期 **1 秒**，满足 ≤1s 指标
- 五道核心工序（上料 / 装配 / 检测 / 打包 / 入库）执行进度与状态（待执行 / 执行中 / 已完成）进度条展示
- 物理产线指示灯（运行 / 停止 / 故障 / 复位）亮灭状态与现场同步，熄灭为灰、运行绿、故障红、复位橙

数据流：`MockDataService.start() → setInterval(1s) → onData(cb) / onLineState(cb) → @State 更新 → UI 重绘`

模型：`model/LineState.ets`（`ProcessStep` / `LineIndicator` / `LineState`）；接口 `IDataService.onLineState()`。
真实接入后由智能计算场景单元推送产线状态，Mock 实现按状态机推进工序进度并同步点灯。

### 模块二：远程产线控制

- 启动 / 停止 / 复位三个操作，全部走 `confirmAndDo(cmd, newStatus)` 二次确认弹窗
- 指令调用 `IDataService.sendCommand(cmd, newStatus)`，**不直接修改设备状态**
- 状态由服务端回推（`onCommand` 回调）后更新 UI，符合"校验后下发"要求
- 操作日志 `logs` 记录：时间、操作人、操作类型、执行结果

### 模块三：数据采集与可视化

- 实时曲线：Canvas 2D 自绘温度（橙）/ 湿度（蓝）双线，保留最近 30 个采样点
- 温度仪表盘：半圆表盘 + 指针，按温度区间变绿 / 黄 / 红
- 历史回看：数据写入 RelationalStore，支持最近 10 / 30 / **60 分钟**查询
- 历史曲线自适应量程 + 均匀抽稀（3600 点 → 150 点），避免绘制过载
- 统计信息：条数、温湿度极值与均值
- 导出：实时数据 `sensor_data.csv`、历史数据 `history_{N}min.csv`

### 模块四：报警管理与异常处理

- 自动检测：温度超限 / 过低、湿度过高 / 过低
- 报警条目完整上下文：类型、发生时间、位置、严重程度等级
- 8 秒内同类型报警去重，避免抖动刷屏
- 支持报警确认，记录确认状态；支持按等级筛选查询
- 阈值可自定义：温度上下限、湿度上下限（Slider 调节）

### 模块五：订单管理与扫码交互

- 扫码下单：输入框模拟扫码枪输入，回车即提交（真机可对接 PDA 扫码广播）
- 手动录入：产品名称、数量（数字校验 > 0）、优先级（高 / 中 / 低）
- 订单状态联动：待生产 → 生产中 → 已完成，进度条随时间推进
- 确认完成二次确认，记录完成时间；支持删除订单

## 四、数据交互协议（已实现，待组委会协议下发后对齐字段名）

> 代码位置：`entry/src/main/ets/service/ProtocolService.ets`。报文组装、国密封装（`seal`）、解封校验（`open`）全部在该类完成；Mock 数据源每秒的传感器数据与控制指令均走「JSON → 国密封装 → 解封 → 解析」完整链路，真实接入 MQTT 后直接复用。

### 4.1 通信方式

| 项 | 约定 |
| --- | --- |
| 主选协议 | MQTT over TLS 1.3 |
| 备选 | HTTPS / WebSocket |
| 数据格式 | JSON（UTF-8） |
| 加密 | SM4 加密业务载荷 + SM3 摘要 + SM2 签名 |

### 4.2 Topic 设计

| 方向 | Topic | 说明 |
| --- | --- | --- |
| 订阅 | `iiot/line/{lineId}/sensor` | 传感器实时数据 |
| 订阅 | `iiot/line/{lineId}/status` | 产线状态回推 |
| 订阅 | `iiot/line/{lineId}/alarm` | 报警推送 |
| 发布 | `iiot/line/{lineId}/command` | 控制指令 |
| 发布 | `iiot/line/{lineId}/history/query` | 历史查询请求 |
| 订阅 | `iiot/line/{lineId}/history/resp` | 历史查询响应 |

> QoS 1（至少一次），保证报警不丢失；配合遗嘱消息做掉线检测。

### 4.3 业务报文（加密前的明文结构）

传感器数据：

```json
{
  "msgId": "b3f1c0a2",
  "type": "SENSOR_DATA",
  "lineId": 1,
  "ts": 1761030000000,
  "data": {
    "temp": 25.6,
    "humi": 60.2,
    "photo": true,
    "status": "RUNNING"
  }
}
```

控制指令：

```json
{
  "msgId": "c9d2e3f4",
  "type": "COMMAND",
  "lineId": 1,
  "cmd": "START",
  "operator": "operator01",
  "ts": 1761030000000
}
```

`cmd` 取值：`START` / `STOP` / `RESET`

报警推送：

```json
{
  "msgId": "a1b2c3d4",
  "type": "ALARM",
  "lineId": 1,
  "ts": 1761030000000,
  "data": {
    "alarmType": "TEMP_HIGH",
    "location": "温控区",
    "level": "HIGH",
    "value": 34.2,
    "threshold": 33.0
  }
}
```

### 4.4 加密后的传输信封

```json
{
  "alg": "SM4_128_CBC_PKCS7",
  "keyId": "sm2-session-key-01",
  "iv": "0f1e2d3c4b5a69788796a5b4c3d2e1f0",
  "payload": "base64(SM4(cipher(JSON)))",
  "digest": "hex(SM3(JSON))",
  "sign": "base64(SM2Sign(digest))"
}
```

接收端校验顺序：SM2 验签 → SM3 摘要比对 → SM4 解密（`ProtocolService.open()` 内已按此顺序实现，任一步失败抛错并由调用方降级处理）。

APP 内「国密算法自检 → JSON信封往返」按钮可现场演示完整往返：明文报文 → 信封（alg/iv/payload/digest/sign）→ 验签解密还原。

## 五、国密加密实现方案

### 5.1 算法分工

| 算法 | 类型 | 密钥长度 | 用途 |
| --- | --- | --- | --- |
| SM2 | 非对称（椭圆曲线） | 256 位 | 会话密钥协商、签名 / 验签 |
| SM3 | 摘要 | 256 位输出 | 报文完整性校验 |
| SM4 | 对称分组 | 128 位 | 业务数据加密 |

### 5.2 密钥协商与通信流程

```
1. APP 生成 SM2 密钥对，将公钥注册到智能计算场景单元
2. 服务端生成 SM4 会话密钥，用 APP 公钥（SM2）加密后下发
3. APP 用 SM2 私钥解密，得到 SM4 会话密钥并缓存
4. 发送：JSON → SM3 摘要 → SM2 签名 → SM4 加密 → MQTT publish
5. 接收：MQTT 消息 → SM2 验签 → SM3 摘要比对 → SM4 解密 → 更新 UI
```

### 5.3 代码位置

| 能力 | 文件 | 方法 |
| --- | --- | --- |
| SM4 加解密 | `service/CryptoService.ets` | `sm4Encrypt` / `sm4Decrypt` |
| SM3 摘要 | `service/CryptoService.ets` | `sm3Digest` |
| SM2 签名验签 | `service/CryptoService.ets` | `sm2SignVerify` |
| 会话密钥 | `service/CryptoService.ets` | `initSessionKey` |
| 一键自检 | `service/CryptoService.ets` | `selfTest` |

技术选型：使用系统自带 `@kit.CryptoArchitectureKit`（`cryptoFramework`），无需引入第三方库，完全满足"国产化技术栈"要求。若组委会后续下发国密 SDK，只需替换 `CryptoService` 内部实现，上层调用不变。

## 六、数据存储设计

### 表结构（RelationalStore）

```sql
CREATE TABLE IF NOT EXISTS sensor_history (
  id     INTEGER PRIMARY KEY AUTOINCREMENT,
  ts     INTEGER NOT NULL,   -- 采集时间戳（毫秒）
  temp   REAL    NOT NULL,   -- 温度 °C
  humi   REAL    NOT NULL,   -- 湿度 %
  sensor INTEGER NOT NULL    -- 光电传感器 0/1
);

CREATE INDEX IF NOT EXISTS idx_history_ts ON sensor_history(ts);
```

### 设计说明

- **索引**：`ts` 建索引，范围查询走索引，避免全表扫描（对应"查询性能"评分点）
- **生命周期**：仅保留最近 2 小时，启动时清理，避免库无限膨胀
- **写入策略**：采集即写，异步非阻塞；失败仅记日志，不影响 UI 刷新
- **降级策略**：接口打通后改为远端 TDengine 优先、本地缓存兜底

| 监控数据刷新 | ≥1 次/秒 | 1 秒定时推送 |

## 八、创新点

1. **国密合规自检面板** — 把 SM2 / SM3 / SM4 的可用性做成 APP 内可现场演示的可视化模块，评委可直接看到密文、摘要与验签结果，而不是停留在文档描述。
2. **端侧边缘缓存** — 在通信链路之外建立本地时序库，弱网 / 断网时历史回看与统计不中断，符合边缘侧设计导向。
3. **数据源可替换架构** — `IDataService` 抽象层让"模拟"与"真实 MQTT"可一行切换，联调风险可控。
4. **自绘图表** — 不依赖三方图表库，用 Canvas 2D 实现双曲线与仪表盘，包体小、渲染可控。
